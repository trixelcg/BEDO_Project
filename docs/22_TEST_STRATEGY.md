# 22 — Test Strategy

**Designed before implementation, per the brief §18.** The project currently has **zero tests**, which is why
`BUG‑06`, `BUG‑14`, `BUG‑15`, `BUG‑05` and `BUG‑27` shipped.

---

## 1. Principle: pin before you refactor

`BEDO‑002` writes tests **against the current code**, before any structural change. They pin behaviour that is
known-good (the physics, the guards, the momentum factors) so the rebuild cannot silently alter it. Only then
does refactoring start.

Tests are also the mechanism the brief's rule *"before changing any physics-domain calculation you must
demonstrate why the existing calculation is incorrect"* is enforced by: the physics spec encodes BEDO's own
spreadsheet values, so changing an equation turns the build red and forces the evidence to be produced.

## 2. Stack

| Layer | Tool | Why |
|---|---|---|
| Unit / integration | **Vitest** | Same Vite transform pipeline; near-zero config |
| React components | **Vitest + Testing Library** | Behaviour, not implementation |
| Headless simulation | **Vitest** driving `createSimulation()` | The runtime is framework-free by design (`docs/15 §2`) |
| 3D scene assertions | **Vitest + headless-gl / `three` null renderer** | Scene-graph and transform assertions without a browser |
| E2E + visual | **Playwright** (chromium, webkit) | Real WebGL, real timing |
| Visual regression | Playwright screenshots + `toHaveScreenshot` | Five named views × key lesson states |
| Performance | Playwright + the WebGL harness from `docs/11 §1.2` | Same methodology as the frozen baseline |
| Accessibility | `@axe-core/playwright` + manual keyboard/SR pass | WCAG 2.1 AA |

  { n: 0.4, q: 15.7144704,   v0: 3.3364056, v: 3.2318574 },

it.each(BEDO)('reproduces BEDO row n=$n', ({ n, q, v0, v }) => {
  expect(flowRateLMin(n, 120)).toBeCloseTo(q, 6);
  const s = jetState(n, 90, 120);
  expect(s.theoreticalVo).toBeCloseTo(v0, 4);
  expect(s.theoreticalV ).toBeCloseTo(v,  4);

// The Fo - Fth identity proves the 2gs form is linear, not sqrt(s)
it('Fo - Fth === rho * A * 2 g s', () => {
  expect(0.87383078 - 0.81992484).toBeCloseTo(1000 * 0.0000785 * 2 * 9.81 * 0.035, 6);

it.each([[30,0.25],[45,0.5],[60,0.75],[90,1.0],[120,1.5],[135,1.707],[180,2.0]])

### 4.2 `apparatus.contract.spec.ts` — the GLB naming contract ★

```ts
import nodeNames from './__fixtures__/apparatus.nodes.json';   // generated by analyze-glb.mjs --nodes
const exposed = new Set(nodeNames.map(gltfName));

it.each(Object.entries(MESH))('MESH.%s resolves', (_, authored) =>
  expect(exposed.has(gltfName(authored))).toBe(true));

it.each(DEFLECTORS)('deflector $id shelf + installed resolve', d => {
  expect(exposed.has(gltfName(d.shelf))).toBe(true);
  expect(exposed.has(gltfName(d.installed))).toBe(true);
});
```

**This ~20-line test is the single highest-value test in the project.** A model re-export that renames nodes
currently fails *silently at runtime* — the exact failure mode documented in `apparatus.ts:11‑26`, which cost
the team weeks and produced the "cover never moved / seven deflectors visible at once" class of bug. It turns
that into a red build with the offending name printed. Regenerate the fixture with:

```bash
node scripts/analyze-glb.mjs public/Bedo_baked_v2.glb --nodes --json > src/domain/apparatus/__fixtures__/apparatus.nodes.json
```

## 5. Regression tests for the audit's findings

Every bug gets a test that fails on the old behaviour. The critical ones:

| Test | Pins |

| `waterJet.spec.ts` | Plume XZ extent at the nozzle within **±15 %** of `2√(A/π)·scale`, for 7 deflectors × 5 flow rates → **`BUG‑03`** |
| `gating.spec.ts` | Clicking the cover at step 2 produces coaching feedback and does **not** toggle the cover → **`BUG‑04`** |
| `deflectorScope.spec.ts` | Selecting a deflector outside the loaded experiment is rejected → **`BUG‑05`** |
| `freeMode.spec.ts` | Free mode records a reading with the valve the student actually set → **`BUG‑06`** |

## 6. E2E

```ts
test('completes the flat-surface experiment end to end', async ({ page }) => {
  await page.goto('/?exp=flat&lang=en');
  await expect(page.getByTestId('loading')).toBeVisible();            // never a black screen
  await expect(page.getByTestId('training-ready')).toBeVisible({ timeout: 4000 });  // B-9
  for (const step of STEPS) { await performStep(page, step); await expectStepAdvanced(page, step); }
  await expect(page.getByTestId('readings-row')).toHaveCount(2);      // exactly the readings taken
  await expect(page.getByTestId('fac-cell').first()).toHaveText(/0\.7[0-9]{3}/);
});
```

Matrix: 4 experiments × 2 languages × {guided, free} — with keyboard-only and mouse variants for the guided
English path.

**No-black-screen guard:** screenshot at 300 ms and assert mean luminance > threshold (`B‑10`).

The layering in `docs/12 §1.1` is only real if it is checked:

`docs/15 §3`).

### 8.1 Performance procedure (matches the frozen baseline)

Reproduce `docs/11 §1` exactly, or the numbers are not comparable:

1. Serve production build; open in Chrome at 1920×1080.
2. **Confirm `document.hidden === false`** — a backgrounded tab throttles rAF to zero and silently
   invalidates every measurement. This invalidated the first attempt during the Phase 1 audit.
3. Inject the WebGL prototype harness (`docs/11 §1.2`) into the page's **main world**.
4. Reset counters, wait 4 s on an idle scene, read draws/frame, tris/frame, FB binds/frame, programs, frame-time
   percentiles.
5. Record VRAM with `analyze-glb.mjs`, payload with `du`, TTFS with the Playwright perf spec.
6. **Append a row to `docs/11 §5`.** Never edit the baseline row.

## 10. Coverage targets

| Area | Target | Rationale |
|---|---|---|
| `domain/` | **100 %** | Pure, tiny, and it is the verified core |
| `simulation/` | ≥ 90 % | Deterministic and headless |
| `lesson/` | ≥ 90 % | Data-driven; the linter covers the definitions |
| `interaction/` | ≥ 80 % | Gesture recognition needs some browser |
| `scene/` | ≥ 50 % | Transform maths and disposal; visuals covered by screenshots |
| `ui/` | ≥ 70 % | Behaviour + a11y contracts |

Coverage is a smoke detector, not a goal. The regression tests in §5 matter more than the percentage.
